│  Greenfield plan for TeamHabits, a habit tracker for small teams. Stack:     │
│  Django 5.2 LTS monolith, htmx 2 and Pico.css 2, SQLite locally and          │
│  PostgreSQL 17 in production, hosted on Render, email through Resend.        │
│  Docs: a PRD, an architecture doc, 8 ADRs, and a roadmap with a timeline,    │
│  cut list, risks and open questions. AGENTS.md and CLAUDE.md hold the        │
│  conventions for agents.                                                     │
│  18 tasks in 3 phases lead to launch on 2026-11-06:                          │
│    Phase 1 (T-001–T-009, weeks 1–2): project setup, CI, sign-in, teams,      │
│  habits, date and streak logic, day logging, the weekly board, and           │
│  production/deploy settings. This is the first deliverable.                  │
│    Phase 2 (T-010–T-013, weeks 3–4): email setup, digest content, sending    │
│  the Monday email only once per person per week, and unsubscribe.            │
│    Phase 3 (T-014–T-018, weeks 5–6): team admin, account deletion,           │
│  security, accessibility, and launch readiness.                              │
│  Subagents (backend, frontend, test-engineer, devops, reviewer) plus /next,  │
│   /review and /status for both Claude Code and OpenCode.                     │
│  5 open questions; none blocks T-001. Choose the sending domain and start    │

◇  Open questions — answer them in .bae/interview.md and run replan ───────────╮
│                                                                              │
│  1. What product name and sending domain should the launch use? (Working     │
│  name: TeamHabits.) — Resend needs SPF and DKIM records on a domain you      │
│  control, and verification can take days. The domain also sets SITE_URL,     │
│  DEFAULT_FROM_EMAIL and the custom domain in T-018. Needed by 2026-10-05.    │
│  2. Do you approve Render (Docker web service, cron job, managed PostgreSQL  │
│   17) as the host, with a target of under about US$30/month? — ADR-008,      │
│  T-009 and T-012 build the Render blueprint. Switching hosts later changes   │
│  render.yaml and the runbooks but not the app. Needed before T-009 (week     │
│  2).                                                                         │
│     Render (default) / Fly.io / Railway / A VPS with Docker Compose          │
│  3. Should 'today' and the Monday email follow one time zone per team, or    │
│  each member's own time zone? — ADR-006 defaults to one team time zone: one  │
│   board, one week boundary, one digest hour. With per-member zones, 'today'  │
│   on the shared board becomes ambiguous. core/dates.py already takes the     │
│  zone as an argument, so only the call sites would change.                   │
│     One time zone per team (default) / Each member's own time zone           │
│  4. Is one team per user enough for v1? — ADR-005 assumes it. It keeps       │
│  request.team unambiguous and keeps the board, digest and deletion rules     │
│  simple. Supporting several teams needs a team switcher and changes URLs     │
│  and constraints.                                                            │
│     One team per user (default) / Several teams per user                     │
│  5. Are binary daily habits enough (done or not done each day), with no      │
│  weekly targets, counts or skip days? — ADR-006 and the streak rules assume  │
│   binary daily logs. Targets such as '3 times a week' would change the data  │
│   model, the streak definition, the board and the digest.                    │
│     Binary daily only (default) / Add weekly targets / Add counts or         │
│  quantities                                                                  │
