◇  Summary ────────────────────────────────────────────────────────────────────╮
│                                                                              │
│  This plan turns the FastAPI service, which today has only `GET /health`     │
│  (`app/main.py:6-8`), into an internal notes API. It will create, list,      │
│  update and delete notes with tags, store them in SQLite, and run on Linux   │
│  with Python 3.12.                                                           │
│  - **Approach:** keep FastAPI and use Pydantic v2 for validation. Store      │
│  data with Python's built-in `sqlite3` module: all SQL sits in one           │
│  repository module, and schema changes are versioned with `PRAGMA            │
│  user_version`. The first task sets up the missing tooling: a formatter      │
│  (`ruff format`), type checking (strict `mypy`), real tests with a coverage  │
│   floor, and CI on GitHub Actions.                                           │
│  - **Phases (8 tasks):** Phase 1 is tooling plus create/read (T-001–T-003).  │
│   Phase 2 adds list, update and delete, which completes the first            │
│  deliverable (T-004–T-006). Phase 3 adds a health check, logging, a systemd  │
│   unit and a live smoke test (T-007–T-008).                                  │
│  - **Risk 1:** there is no authentication, by design. Anyone who can reach   │
│  the port can read or delete every note, so where the service sits on the    │
│  network is the only protection.                                             │
│  - **Risk 2:** SQLite handles one writer at a time. Running several worker   │
│  processes, or starting two at once, can cause lock errors or a race while   │
│  updating the schema. The plan runs a single uvicorn worker, uses SQLite's   │
│  write-ahead log (WAL) mode, and takes the write lock before migrating.      │
│  - **Risk 3:** some assumptions are unconfirmed. There is no git remote, so  │
│   the CI host is a guess. The validation limits are my choice, and without   │
│  a lockfile dependency versions can drift.                                   │
│  - **Next:** answer the questions below (none of them block work), then run  │
│   `/next`. It will pick up T-001, which the platform agent handles.          │
