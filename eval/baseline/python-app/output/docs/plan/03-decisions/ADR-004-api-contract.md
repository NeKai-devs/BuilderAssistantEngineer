# ADR-004: REST contract. PATCH updates, offset pagination, FastAPI default errors, integer IDs

- Status: accepted
- Date: 2026-09-26

## Context
Clients are internal scripts and services (PRD). The brief asks for create, list, update and delete, with validation. The existing service follows FastAPI defaults (`app/main.py`).

## Decision
- **Resources:** `/notes` and `/notes/{note_id}`.
- **Create:** `POST /notes` returns 201 with the note in the body and a `Location` header.
- **Update:** `PATCH /notes/{note_id}` is a partial update.
  - At least one field is required, and explicit `null` is rejected.
  - A provided `tags` list replaces the whole set.
  - The last write wins.
- **Delete:** `DELETE` returns 204 and is permanent.
- **List:** `GET /notes?limit=&offset=&tag=` returns an envelope `{"items","total","limit","offset"}`, ordered by `updated_at` DESC then `id` DESC.
  - `limit` defaults to 50 (max 200).
  - Repeated `tag` parameters combine with AND.
  - Query parameters are parsed with a FastAPI query-parameter model (FastAPI ≥ 0.115).
- **IDs:** SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`, so IDs are never reused.
- **Timestamps:** `created_at` and `updated_at` are UTC, generated by the server, and serialized as ISO 8601.
- **Errors:** FastAPI defaults. 422 `{"detail": [...]}` for validation errors; `{"detail": "Note not found"}` for 404. Request bodies reject unknown fields (`extra="forbid"`).

## Alternatives considered
- **PUT full replacement:** lost. Clients would have to resend the whole document including tags; PATCH covers both uses. It can be added later if asked for (open question 4).
- **Cursor pagination:** lost. It is more complex, and offset pagination is adequate below 100k rows.
- **UUIDs:** lost. IDs are generated in only one place, and integers are easier to use from curl. They are guessable, but that doesn't matter without auth.
- **RFC 9457 problem+json or a custom error envelope:** lost. It would diverge from FastAPI's generated OpenAPI and add code; it can be layered on later.
- **Soft delete and ETag/If-Match:** deferred; not requested.

## Consequences
- The contract is simple, curl-friendly, and fully described by the generated OpenAPI at `/docs`.
- Two clients updating the same note at once overwrite each other silently. This is acceptable for internal use, per assumption A6.
- The FastAPI floor is raised to `>=0.115` (T-001) so query-parameter models are available.
